# MuJoCoによる倒立二輪ロボットのシミュレーション

## 概要と目的

[MuJoCo](https://mujoco.org/)を使用した、二輪で自立するロボットのシミュレーションです。ロボットは線形二次レギュレータ（LQR）コントローラーでバランスを維持します。この例では、MuJoCoのシミュレーション画面をQtアプリケーション（PySide6）に埋め込み、UIウィジェットからロボットを操作できるようにしています。

同じシミュレーションをPyBulletで実装した後（[こちら](https://github.com/lachlanhurst/balance-robot-pybullet-sim)を参照）、PyBulletの[Stable-Baselines3](https://stable-baselines3.readthedocs.io/) / [Gymnasium](https://gymnasium.farama.org/index.html)対応がやや不十分だと感じました。プロジェクトがまだ初期段階だったこともあり、MuJoCoに移行することにしました。

![倒立二輪ロボットのシミュレーション動画](./docs/mujoco_sim.gif)

## 開発環境のセットアップ

リポジトリをクローンします。

    git clone https://github.com/lachlanhurst/balance-robot-mujoco-sim.git
    cd balance-robot-mujoco-sim

このリポジトリに含まれるconda環境ファイルの使用を推奨します。以下のコマンドで、新しいconda環境 `robot-mujoco-simulation` を作成して有効化します。

    conda env create -f conda-environment.yaml
    conda activate robot-mujoco-simulation

## LQRパラメーターの計算

LQRパラメーターはすでに[ソースコードに含まれています](./src/simulation/robot_lqr.py)。ロボットの物理特性（[`robot-02.xml`](./src/simulation/robot-02.xml)で定義）を変更しない限り、再計算は不要です。

再計算が必要な場合は、[PyBullet版シミュレーションのリポジトリ](https://github.com/lachlanhurst/balance-robot-pybullet-sim)に記載された手順に従ってください。

## シミュレーションの実行

次のコマンドでシミュレーションを実行します。事前に `robot-mujoco-simulation` 環境を有効化してください。

    python src/simulation/simulate_robot.py

## INT8ニューラル制御（2026-10-09）

`python -m pip install -r requirements-int8.txt` を実行すると、GUIの **NN INT8** で `models/ROBOT.TFL` を実行できます。既存の **Neural Network** はFP32モードです。INT8モデルと対応する `ROBOT.json` を一緒に保持してください。通常条件18試行でFP32と同じく各20秒倒立・転倒0回を確認しました。最小版は4→16→16→1、336 MAC、2,768 Bです。PSC-ONEの現行ランタイム向けには、等価ReLU版 `ROBOTFC.TFL` もあります。

角度RMS、推論誤差、外乱復帰、全24試行の結果、演算子、移植制約、再実行方法は [INT8検証レポート](docs/int8-validation.md) を参照してください。

## AUTO指令モード

**Robot Control → Command mode** で **AUTO** を選ぶと、Speed/Yawスライダーを操作せずに、画面上のロボットを自動運転できます。LQR、読み込み済みのNeural Network、読み込み済みのReinforcement Learningで使用できます。起動時は **MANUAL** です。

AUTOは、学習用の9種類の指令パターン（停止、緩やかな前進・後退、段階的な速度変更、前進・停止・後退、左・右旋回、速度とヨーの同時指令、ランダム指令）を順に実行します。各エピソードはシミュレーション時間で最大8秒です。どの方向でも45°を超えて傾いた場合や、物理状態が無効になった場合は、自動リセットして次のパターンへ進みます。MANUALに戻すまで繰り返します。速度は±0.6 m/s、ヨー指令は±2 rad/s以内で、200 Hzで滑らかに変化します。エピソード、パターン、経過時間、転倒回数、適用指令を表示し、スライダーは指令値の表示のみとなり、手動入力を無効にします。

AUTOに切り替えると、ほぼ直立した姿勢へリセットします。**Reset** はAUTOと選択中のコントローラーを維持し、パターンを最初からやり直して転倒回数をクリアします。コントローラーの切り替えでは実行中のエピソードを維持します。MANUALに戻すと、物理状態をリセットせずに両指令とスライダーをゼロにし、手動操作を再開できます。

NNとRLの**学習指令は、すでに別シミュレーションで自動生成されています**。**Train NN**、**Train new RL**、**Continue loaded RL** で学習・保存を開始でき、AUTO運転と並行して実行できます。画面上のAUTO運転は使用中のモデルの動作確認であり、モデルの重みを更新するものではありません。RL学習では、`balance` は目標速度ゼロを維持し、`velocity` は前進・後退の目標値を自動生成します。ヨー指令はゼロです。AUTOでの旋回は動作確認であり、RLによる旋回学習ではありません。

## ニューラルネットワークコントローラー

起動時の既定コントローラーは引き続きLQRです。Controller選択欄では、物理状態をリセットせずに **LQR** と **Neural Network** を切り替えられます。後述する **Reinforcement Learning** も選択できます。LQRと教師ありNNは、どちらも従来と同じ200 Hzの制御、0.975/0.025のフィルター、`MAX_MOTOR_VEL = 500 rad/s`、およびヨー方向の指令の合成式（`left = -velocity + yaw`、`right = velocity + yaw`）を使用します。Resetは選択中のコントローラーを維持し、フィルター、指令、時刻をクリアします。シミュレーション、描画用シーンの準備、Reset、コントローラーの差し替えは、共通のロックで同期します。

### インストールとGUI

既存のPython環境で、`balance-robot-mujoco-sim` ディレクトリから実行します。

```bash
python -m pip install -r requirements-nn.txt --index-url https://download.pytorch.org/whl/cpu
python -B src/simulation/simulate_robot.py
```

付属の `models/robot_nn.npz` により、すぐにNNを選択できます。PyTorchやモデルがなくてもLQRは動作します。有効なモデルが利用できるまで、NNの選択は無効になります。モデルが破損している場合は学習パネルに表示されますが、LQRの起動は妨げません。PyTorchは学習時のみ必要です。NN制御では、学習済みMLPを等価なNumPy形式にエクスポートしたものを評価するため、シミュレーションループ内でオプティマイザー、モデルの読み込み、PyTorchのスレッドプールは動作しません。

右サイドバーの **Supervised NN** タブで **Train NN** をクリックします。EpisodesとEpochsはこのパネルで変更できます（既定値：120 / 240）。パネルにはIdle / Collecting Data / Training / Validation / Saving Model / Completed（失敗時はFailed）の状態、収集の進捗、サンプル数、エポック数、学習損失 / 検証損失 / 最良の検証損失、学習率、経過時間、リアルタイムの損失グラフが表示されます。また、Current Episode / Total Episodes、Current Auto Speed/Yaw Command、Current Scenario、エピソード内のシミュレーション経過時間、Number of fallsも表示されます。自動指令値はデータ収集中のみ表示されます。損失は物理単位 `(rad/s)^2` の平均二乗誤差（MSE）で、グラフの縦軸は対数スケールです。小さい画面ではサイドバーをスクロールできます。

学習は、専用のMuJoCoモデルとデータを持つ別プロセスで、CPUの学習スレッドを1本使用して実行されます。進捗を非同期に受信し、表示ラベルを10 Hzで更新します。学習中も画面上のシミュレーションを続行でき、コントローラーの切り替えやResetも可能です。完了するとモデルを保存して読み込みます。すでにNNが選択されている場合は、シミュレーションのロック内で新しい重みの予測器に置き換えます。それ以外の場合はLQRの選択が維持されます。学習に失敗しても、使用中の予測器は維持されます。アプリケーションを閉じると、シミュレーションを停止し、実行中の学習プロセスも終了します。

### データと学習

```bash
python -B src/simulation/neural_training.py --episodes 120 --duration 8 --epochs 240 --seed 42
```

5 msごとの制御周期で、次の順序で記録します。

1. 制御用ピッチ角（ラジアン、LQRと同じ符号）。
2. フィルター処理後のピッチ角速度（rad/s）。
3. フィルター処理後の、前進を正とする車輪角速度（rad/s）。
4. 目標並進速度（m/s）。

教師信号は、制限適用後かつ**ヨー指令を合成する前**の実際のLQRモーター速度です。`(right_motor_command - left_motor_command) / 2` として取得します。センサーとフィルターは制御周期ごとに1回サンプリングします。物理演算の時間刻みは従来どおり25マイクロ秒で、1制御周期あたり200回の物理サブステップを実行します。オフラインの収集・評価では、シミュレーション時刻に基づいて制御を実行します。GUIでも物理演算200ステップごとに制御を実行し、実時間は画面上のシミュレーションの進行速度を調整するためだけに使用します。描画が遅くなっても、制御周期やシミュレーション時間に対するフィルターの実効更新頻度は変わりません。

**Train NN** は、スライダー操作なしで、LQRによる自動収集 → 学習 → 学習に使用しないデータによる検証 → モデルの保存・読み込みを実行します。自動指令は独立した学習用シミュレーションにのみ適用されます。学習中も、Speed/Yawスライダー、コントローラーの選択、Resetは、従来どおり画面上のシミュレーションを操作します。

停止、緩やかな前進、緩やかな後退、段階的な速度変更、前進 → 停止 → 後退、左旋回、右旋回、速度とヨーの同時指令、ランダム指令の9シナリオを順に実行します。目標値はシミュレーション時間で0.5～3秒間保持し、制御周期ごとにランダム化することはありません。適用指令はゼロから徐々に変化し、変化率の上限はSpeedが毎秒0.15 m/s、Yawが毎秒1.0指令rad/sです。進行方向を反転するシナリオでは、ゼロ指令を実際に保持する区間を含め、各目標値を2秒間保持します。最後の保持区間は、エピソードの終了や転倒によって短縮される場合があります。

GUIの範囲は引き続き速度±4 m/s、ヨー指令±10 rad/sです。自動学習では、そのうち控えめな範囲であるSpeed ±0.6 m/s、Yaw ±2 rad/sを使用し、緩やかな前進・後退は0.15～0.3 m/sとします。Yawは従来の車輪への合成指令であり、計測した車体のヨー角速度ではありません。これらの上限と変化率は `src/simulation/auto_commands.py` に定義されています。

各エピソードではMuJoCoと教師側のすべてのフィルターをリセットし、指令と速度をゼロから開始します。初期姿勢には、シード付き乱数で小さな傾き（ピッチ±0.08 rad、ロール±0.03 rad）とランダムな方位を与えます。どの方向でも車体の傾きが45°を超えると、エピソードを即座に終了し、収集処理は自動的にリセットして次に進みます。転倒回数も記録します。既定値は、最大8秒のエピソードを120回です。各パターンを網羅し、学習用と検証用のエピソードを分離するため、最低18エピソード（各シナリオ2回）、1エピソードあたり最低6秒が必要です。Total Episodesは固定の試行回数であり、転倒により各試行が短くなる場合があります。

収集後、シナリオごとにエピソード単位で学習用または検証用に振り分けます（約20%を検証用とし、各シナリオで最低1エピソードを確保）。次に、それぞれの分割内で、軌跡全体からサンプルをランダムに間引き、最もサンプル数が少ないシナリオに揃えます。これにより、転倒があっても、各分割内で9パターンすべてのサンプル数が厳密に等しくなります。サンプルの複製は行いません。GUIのCollected samplesは収集した生のサンプル数を示します。レポートでは収集数と採用数を区別し、各シナリオの学習用・検証用サンプル数を記載します。停止状態への偏りを防ぐため、長いエピソードのサンプルが一部破棄される場合があります。

PyTorchのMLPは `4 → 16 → 16 → 1` で、隠れ層の活性化関数はLeakyReLU(0.1)です。入力と出力の平均・標準偏差は、学習用エピソードのみから求めます。各シナリオのエピソードの20%（最低1エピソード）を丸ごと検証用に確保し、隣接する時刻のサンプルからの情報漏洩を防ぎます。学習では、エポック数の75%にわたってコサイン減衰する学習率でAdamを使用し、その後、全サンプルを使うLBFGSで精度を高めます。保存するのは検証MSEが最小のチェックポイントであり、必ずしも最終エポックではありません。すべての乱数シードを固定し、評価シナリオを正規化パラメーターや重みの学習に使用することはありません。

生成されるファイル（保存先は `--output /path/name.npz` で変更できます）：

| ファイル | 内容 |
| --- | --- |
| `models/robot_nn.npz` | 推論用の重み、特徴量の順序、活性化関数、入出力の正規化情報。アトミックに置き換えます |
| `models/robot_nn.pt` | PyTorchのstate dict、ネットワーク構成、同じ正規化情報。`torch.load(..., weights_only=True)` で読み込みます |
| `models/robot_nn.data.npz` | 入力、実際の教師信号、エピソードID、検証用マスク、シナリオ名、適用値・目標値のSpeed+Yaw指令、エピソード内のシミュレーション時刻 |
| `models/robot_nn.training.json` | 設定、サンプルの値域、データ分割、損失、シナリオ別件数、転倒、初期状態・指令スケジュール、エポックごとの履歴 |

### 評価と回帰チェック

```bash
python -B src/simulation/evaluate_controllers.py --duration 10
python -B -m unittest discover -s tests -v
python -B tests/gui_neural_smoke.py  # 動作するデスクトップ/OpenGL表示環境が必要
```

評価では、同じ初期状態、目標値スケジュール、ヨー指令、物理演算・制御の時間刻みでLQRとNNをそれぞれ独立に実行します。10のシナリオで、静止時のバランス、緩やかな前進・後退のランプ指令、急な前進・後退指令、進行方向の切り替え、旋回、高速指令を検証します。結果を `models/robot_nn.evaluation.json` に書き込み、概要を表示します。`--model` と `--output` で、別のモデルやレポートの保存先を指定できます。

評価指標は、`|pitch| > 45°` になるまでのバランス維持時間（指定時間を上限とする）、ピッチ角のRMS、ピッチ角の絶対値の最大値、フィルター処理前の前進を正とする車輪角速度に車輪半径を掛けて算出した速度誤差のRMS、およびNN/LQRモーター出力のRMSEです。出力誤差は、各コントローラーの軌跡上で**同一の入力状態**に対して計算し、制限適用後・ヨー指令合成前の値を使用します。各シナリオの計測は最初の転倒までであり、短時間で失敗した実行を良好な追従と解釈してはいけません。概要の値は各シナリオの単純平均ですが、最大ピッチ角のみ全体の最大値です。

## 強化学習（PPO）

RLは、Stable-Baselines3のPPOと小規模なTanh MLP（方策の平均を出力する `7 → 32 → 32 → 1` のネットワーク、および `7 → 32 → 32 → 1` の価値ネットワーク）を使用する独立したコントローラーです。新規学習はランダムな重みから開始し、報酬のみを使用します。教師ラベルのためにLQRを呼び出したり、教師ありNNの重みを取り込んだりすることはありません。従来のNNの `.npz` / `.pt` 形式、およびLQRの式とフィルターは変更していません。同梱の `models/robot_rl.rl.zip` は、501,760ステップ時点で選択したbalance段階のモデルです。

2026-10-08の再検証では、初期姿勢を変えた4試行で各60秒間、転倒せず動作しました。後半の速度RMSは約0.0175 m/sで、ゆっくりした移動は残っています。`evaluate_rl.py` の変位まで含む厳しい停止判定には合格していません。走行指令は未学習です。元の100,352ステップのモデル（学習中652試行すべて転倒）は `models/robot_rl.before-balance-fix.rl.zip` に保存しています。602,112ステップまで追加した候補は15〜21秒で転倒したため採用しませんでした。詳細は [`docs/rl-balance-fix-validation.json`](docs/rl-balance-fix-validation.json) を参照してください。

アプリを再起動し、**Load RL** で `models/robot_rl.rl.zip` を読み込み、**Reinforcement Learning / MANUAL** を選択してSpeed/Yawをゼロにし、**Reset** を押して確認してください。

### インストール、学習、評価、実行

上記の既存のMuJoCo/NumPy/SciPy/PySide6環境を使用します。RLには追加でGymnasium、Stable-Baselines3、PyTorchが必要です。CPUで実行できます。`balance-robot-mujoco-sim` ディレクトリから実行してください。

```bash
python -m pip install -r requirements-rl.txt
# 第1段階：目標速度ゼロで自立を学習。次の段階に進む前に評価します。
python -B src/simulation/rl_training.py --stage balance --steps 1000000 \
  --config config/rl-default.json --output models/rl-balance.rl.zip
python -B src/simulation/evaluate_rl.py --rl-model models/rl-balance.rl.zip \
  --rl-only --duration 8 --output models/rl-balance.evaluation.json
# 第2段階：PPOとオプティマイザーの状態を復元し、前進・後退の目標値を導入します。
python -B src/simulation/rl_training.py --resume models/rl-balance.rl.zip \
  --stage velocity --steps 1000000 --output models/robot_rl.rl.zip
# 3種類とも同じ初期姿勢、速度、目標値、ヨー指令、時間刻み、転倒閾値を使用します。
python -B src/simulation/evaluate_rl.py --rl-model models/robot_rl.rl.zip \
  --nn-model models/robot_nn.npz --duration 8 --output models/rl-evaluation.json
python -B src/simulation/simulate_robot.py
```

指定したステップ数は例であり、収束を保証するものではありません。`--steps` は追加する**制御ステップ**数であり、物理サブステップ数ではありません。PPOは完全なロールアウト単位（既定では2,048ステップ）に切り上げます。スモークテスト用に、`--rollout-steps` には64の倍数を指定できます。この実装でのPPOの既定値は、バッチサイズ64、1ロールアウトあたり最適化10エポック、学習率0.0003、割引率0.999、GAE lambda 0.98、探索ノイズの初期対数標準偏差−2（約4 rad/s）、シード42、CPUスレッド数1です。CLIの標準出力には進捗をJSONで出力します。Ctrl-C/SIGTERMを受けると、次のコールバックで停止・保存を行うよう要求します。学習・評価では描画や実時間に合わせる待機を行いません。参照先は[SB3 PPO](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html)と[Gymnasiumの終了・打ち切り処理](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)です。

**RL (PPO)** タブでは、次の操作ができます。

- **Train new RL**：ランダムな状態から学習を開始します。`balance` または `velocity` と、学習ステップ数を選択します。
- **Continue loaded RL**：読み込んだスナップショットの状態をそのまま復元し、選択した段階で学習を再開します。
- **Stop and save**：協調的に停止し、バンドルを書き込みます。**Training output…** では、開始前に保存先を選択します（既定は `models/robot_rl.rl.zip`）。
- **Load RL**：保存済みバンドルを検証して読み込みます。**Save loaded RL as…** は、学習状態を含むそのスナップショットを別のファイルにコピーします。
- 総ステップ数、完了エピソード数、直近100完了エピソードの平均累積報酬・平均継続時間、累積転倒回数・無効エピソード数、毎秒の制御ステップ数により、学習の状況を表示します（再開時には復元した履歴を含みます）。読み込んだモデル自体のステップ数もメッセージに表示します。

**指定ステップ数の終了は、倒立の習得を意味しません。** 学習後は `Evaluating` に進み、結果を `Validated`（評価合格）または `Needs training`（追加学習が必要）で表示します。学習とは別の固定シード4個で、探索ノイズなしの方策を1エピソード以上（遅れて起きる転倒も検出するため最低30秒、速度変更から停止まで収まるよう必要に応じて延長）評価します。全試行で転倒せず、後半の速度RMSが0.02 m/s未満、最大速度が0.05 m/s未満であることが合格条件です。velocity段階では、さらに移動目標の4試行で転倒ゼロかつ速度追従RMSEが0.08 m/s未満であることも確認します。結果はバンドルに保存し、GUIの **Saved policy validation** に表示します。途中停止した学習や評価結果のない旧バンドルは **Not evaluated**（未評価）です。合格はこれらの条件での結果であり、旋回や動作中の任意の制御切り替えまで保証するものではありません。

不合格でも継続用のモデルは保存されます。まず `balance` で **Continue loaded RL** を使って追加学習してください。**Train new RL** は毎回ランダムな重みからやり直します。動作確認は **MANUAL** でSpeed/Yawをゼロにし、**Reset** を押してから行ってください。AUTOはbalance専用モデルに対しても走行指令を出します。

GUIは常にLQRで起動します。RLはバンドルの読み込みに成功するまで無効であり、起動時にRLファイルを自動で読み込むことはありません。学習の成功時、または停止・保存の完了時には新しいスナップショットを読み込みますが、選択中のコントローラーは変更しません。RLが選択されている場合は、シミュレーションのロック内で差し替えます。学習は `QProcess` 内で独立したMuJoCoモデルとデータを使用し、進捗はQtのシグナルで届きます。読み込みは `QThread` で実行し、結果もシグナルで返します。使用中の予測器が学習器と重みを共有することはありません。学習や読み込みに失敗した場合は、前の予測器を維持します。アプリケーションを閉じると、学習プロセスに協調的な停止・保存を要求して待機します。子プロセスが応答しない場合は、タイムアウト後に終了・強制終了します。強制終了では現在の学習結果を失う可能性がありますが、アトミックな書き込みにより、以前の完全なバンドルは保護されます。Reset、Speed（±4 m/s）、Yaw（指令値±10 rad/s）、制御状態表示は引き続き利用できます。Resetは選択中のコントローラーを維持します。

### 物理モデル、アクション、実行タイミングの仕様

学習には、**変更を加えていない** `src/simulation/scene.xml` と `robot-02.xml` を使用し、独立した `MjModel` / `MjData` を持たせます。シーンの時間刻み25 µsは、5 msの制御周期をちょうど分割できます。つまり、**1アクションあたり物理演算200ステップ、制御周波数200 Hz**です。GUI、RL、オフラインのコントローラーは、`control_timing.py` の周期検証処理を共有します。GUI制御はシミュレーション時刻ゼロから開始し、物理ステップ数を数えます。学習と評価では、実時間に依存せず、一度に200ステップずつ進めます。

XMLのアクチュエーターは `<velocity gear="1" kv="0.9">` です。`ctrl` は、トルクでも速度の増分でもなく、**rad/s単位の関節角速度の絶対目標値**です。関節のアクチュエーター力の範囲±5は、アクチュエータートルク（これらのヒンジではN·m）を制限するもので、速度指令の範囲を定めるものではありません。既存の共通速度指令の制限は±500 rad/sです。PPOのスカラーアクション `a` は `[-1, 1]` にクリップされ、既定では `v = 30 * a` rad/sに変換されます。`action_scale` は最大500まで調整できます。初期の探索範囲を小さくしても、LQR/NNの制限値は変わりません。

すべてのコントローラーで、従来の合成式 `left = -v + yaw`、`right = v + yaw` を使用します。共通速度指令の制限はヨー指令合成の**前**に適用するため、従来と同様に、最終的な車輪指令はヨーの加算分だけ±500を超えることがあります。左右の車輪の関節軸は互いに逆向きです。前進を正とする車輪角速度は `(-left_qvel + right_qvel)/2`、車輪半径は0.034 m、車体前方はローカル座標の **−Y** です。Yawは引き続き手動で合成する車輪指令であり、学習した車体のヨー角速度ではありません。RL学習ではヨー指令をゼロとします。

### 観測と正規化

`rl_control.py` は、Gym環境とGUIの `RobotRL` に共通する、観測・アクション処理の唯一の実装です。RLは生のセンサー値を使用し、LQR/NNのローパスフィルターは使用しません。`R` を車体座標からワールド座標への回転行列、`qvel_xyz` を自由関節のワールド座標系での並進速度とすると、観測の順序は厳密に次のとおりです。

| インデックス | 量 | 元の単位 / 定義 | 固定の除数 |
| --- | --- | --- | ---: |
| 0 | 制御用ピッチ角 | rad; `-atan2(R[2,1], R[2,2])` | 0.35 |
| 1 | ピッチ軸の角速度 | rad/s; 自由関節のローカルX軸角速度。直立付近ではピッチ角の時間微分と逆符号 | 5 |
| 2 | 前進方向の車輪速度 | m/s; `(-left_qvel + right_qvel) * 0.034 / 2` | 1 |
| 3 | 実際の車体前進速度 | m/s; `-dot(qvel_xyz, R[:,1])` | 1 |
| 4 | 目標前進速度 | m/s | 1 |
| 5 | 前回適用した共通アクション | 無次元。前回の `v/action_scale`。リセット時はゼロ | 1 |
| 6 | 横方向の傾き | rad; `atan2(R[2,0], R[2,2])` | 0.35 |

各特徴量から差し引く平均値はゼロとし、表のスケールで割り、±10にクリップしてfloat32に変換します。これらは**固定の物理スケール**です。データから推定する統計量や逐次更新する統計量はなく、`VecNormalize` も使用しません。スケール、クリップ値、特徴量の意味と順序、アクションの変換、200 Hzの周期を各バンドルに保存します。学習と推論は同じ正規化を使用し、更新は行いません。評価とGUI推論では、常に `deterministic=True` でPPOを呼び出します。RLの状態表示におけるピッチ角速度は生の値で、速度誤差は実際の車体速度を使用します。LQR/NNでは、従来のフィルター処理済みの車輪速度に基づく状態量を維持します。

### エピソード、カリキュラム、報酬

`config/rl-default.json` には、環境と報酬のすべての設定が含まれます。新規学習では、変更したJSONを `--config` で指定できます（省略したキーには既定値を使用）。継続学習では保存済み設定を復元し、互換性のない上書きは拒否します。変更できるのはカリキュラムの段階だけです。エピソード開始時には、シード付き乱数でピッチ±0.06 rad、横方向の傾き±0.02 rad、方位±π、X/Y軸角速度±0.05 rad/sを与えます。車輪速度と前回アクションはゼロです。クォータニオンはMuJoCoの `w,x,y,z` 順を使用します。RL選択時のGUIのResetは、同じ姿勢分布を使用します。LQR/NNのReset動作は維持します。

`balance` では目標速度をゼロに保ちます。`velocity` では、±0.4 m/sの範囲から一様に選ぶ移動目標と、厳密にゼロの停止目標を交互に設定します。最初はゼロを保持し、各目標まで最大0.15 m/s²で変化させた後、到達した値を2秒間保持します。姿勢のランダム化と指令の乱数生成器には、GUIとは独立にシードを設定します。アクションをサンプリングする前に目標値を観測へ含めます。報酬にはそのアクションに対応する指令を使用し、次の観測には次の指令を含めます。どちらの段階も教師は使用しません。

**5 msの状態遷移**ごとの報酬は、ステップ後の状態を使う以下の項の合計です。`tilt = acos(R[2,2])`、`e = target - actual_body_forward_speed` とし、`a` はクリップ後の正規化済みアクションです。

| 項目 | 既定の式 |
| --- | --- |
| 生存 | `+1.0` |
| 速度追従 | `+2.0 * exp(-(e / 0.08)^2)` |
| 傾き | `-0.6 * min((tilt / 0.12)^2, 1)` |
| ピッチ角速度 | `-0.1 * min((pitch_rate / 1.0)^2, 1)` |
| 操作量 | `-0.02 * a^2` |
| アクションの変化 | `-0.03 * ((a - previous_a)/2)^2` |
| 転倒 / 無効な物理状態 | 他のすべての項を置き換え、**合計−10** |

**どの方向でも**傾きが45°を超えた場合、物理状態に非有限値がある場合、またはMuJoCoの警告が発生した場合は、`terminated=True` とします。12秒の時間上限では `truncated=True` のみを設定し、PPOがタイムアウト時にブートストラップできるようにします。終了時の無効な観測値は、有限値であるゼロに置き換えます。次の学習エピソードでは、物理状態とコントローラーの内部状態をリセットします。終了済みの基礎Gym環境をリセットせずにステップ実行することは拒否されます。

終了に至らないステップでのペナルティの最大値は0.75に制限されるため、追従が悪くても、有効な状態で生存している各ステップの報酬は0.25以上になります。したがって、早期に転倒して生存中の負の報酬を避けることで、累積報酬を増やすことはできません。設定の検証では、この下限が正であることを強制します。姿勢とアクションのコストが等しい場合、ゼロでない目標値に追従するほうが、停止するより必ず良い報酬になります。また、目標速度0.3 m/sで、少し傾いて追従する場合と直立したまま停止する場合を比較するテストもあります。追従には車体の動きを使用し、車輪の空転だけで報酬を得ることを抑えます。これらは報酬設計のチェックであり、**学習によるあらゆる抜け道を防ぐ証明でも、収束の証明でもありません**。平均報酬だけでなく、ゼロでない目標値への追従と転倒も評価してください。方策が動かなくなったり転倒したりする場合は、より長い学習と、報酬・探索の調整が引き続き必要です。

### 停止とつまみ操作の確認

**Controller: Reinforcement Learning / Command mode: MANUAL** を選択し、SpeedとYawをゼロにしてResetします。RLのSpeedつまみは読み込んだモデルの学習範囲（既定±0.4 m/s）を使用し、急な操作も学習時の変化率で渡します。`balance` だけでは走行指令を学習しません。静止を評価してから `velocity` へ進めてください。

評価結果の `stopping` には、ゼロ目標シナリオ後半の速度RMS、最大速度、移動距離、変位を保存します。転倒せず、速度RMS < 0.02 m/s、最大速度 < 0.05 m/s、変位 < 0.05 m のとき合格とします。絶対位置の保持を保証する判定ではありません。

新しい報酬は小さな速度誤差と姿勢の揺れを強く評価し、velocity学習にも停止保持を含めます。既存のversion 1モデルは読み込み・継続学習が可能ですが、元の報酬とPPO設定を保持します。新しい既定値を使う場合は **Train new RL** で新規学習してください。コードの更新だけでは既存モデルは改善しません。出力先を同じにする場合は、既存モデルを先に別名で保存してください。

### バンドル形式、継続学習、比較

アトミックに置き換えられる `.rl.zip` には、`ppo.zip`（SB3の方策・価値・オプティマイザーの状態とカウンター）、`metadata.json`（バージョン付きの観測・アクション仕様、正規化、制御周期、報酬・カリキュラム設定、XMLのSHA-256ハッシュ、ライブラリのバージョン、学習カウンター・履歴、環境の乱数生成器）、`rng.pt`（Python/NumPy/PyTorchの乱数生成器の状態）が含まれます。教師ありNNのファイルとは別の形式です。特徴量の仕様、物理モデルのXML、方策の次元に互換性がない場合は拒否します。SB3のチェックポイントにはシリアライズされたPythonデータが含まれるため、信頼できるモデルファイルのみ読み込んでください。

継続学習では、PPOとAdam、累積ステップ数、乱数生成器の状態を復元し、**新しいエピソード**を開始します。中断された物理軌跡をその時点から厳密に再開するわけではありません。協調停止時の未完了のPPOロールアウトは破棄しますが、完了済みのオプティマイザー更新は維持します。このため、完了ステップ数には、未完了のロールアウトのサンプルが含まれる場合があります。報酬の正規化は使用しません。GUI推論から保存したスナップショットには、継続学習のために元のオプティマイザーと乱数生成器の状態を保持します。

`evaluate_rl.py` は、正負の初期傾き、前進・後退のランプ指令、前進・停止・後退、手動のヨー指令合成という6つの決定論的シナリオで、3種類すべてのコントローラーを実行します。`--rl-only` を指定すると、教師ありNNのファイルなしでチェックポイントを評価できます。レポートには、シナリオごとの初期qpos/qvel、転倒率、転倒までの時間（指定時間を上限とする）、実際の車体速度の追従RMSE、車輪速度の追従RMSEが含まれます。すべてのコントローラーに同じシナリオ指令と終了条件を適用します。誤差は最初の転倒まで計測するため、早く転倒する方策ではRMSEが見かけ上小さくなる場合があります。生存時間と転倒率を併せて確認してください。従来の `evaluate_controllers.py` も引き続き利用でき、ピッチ角のみの転倒判定とフィルター処理を用いた従来の制御方式で、過去のLQR/NN比較を実行できます。
